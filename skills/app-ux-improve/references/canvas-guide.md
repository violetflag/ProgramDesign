# 개선안 캔버스 만들기 (Claude Design)

목적은 "고치기 전에 보여 주고 고르게 하는 것"이다. 취향이 갈리는 변경(서체, 바탕색, 화면 구조)은
그림을 보고 결정하게 하는 쪽이 코드로 넣었다 되돌리는 것보다 훨씬 빠르다.

## 만들기

1. Artifact 도구에 `action: "quickstart"`, `intent: "design"`으로 Design 타입의 주소를 받는다.
2. `type_url`로 새 캔버스를 만든다. 제목은 "<앱> 디자인 개선안" 또는 "<앱> 디자인 개선안 2"처럼 사용자가
   부르는 이름. 이미 캔버스가 있고 내용이 이어지면 그 캔버스를 읽어 보드를 추가해도 되지만, 이전 제안이
   이미 구현됐으면 새 캔버스가 깔끔하다.
3. 작업 폴더(스크래치) 아래 `canvas/project/`에 `canvas.json`과 `*.dc.html`을 쓰고 `root`로 올린다.
   `canvas.json` + 첫 보드(`Main.dc.html`)를 먼저 올리고, 나머지 보드는 하나 쓰고 하나 올린다.

## 배치

줄마다 하나의 주제. 왼쪽 "현재", 오른쪽 "개선", 맨 오른쪽에 초록 메모(근거).

```
title1 메모(y = 줄 시작 - 300)   "1 · 요약 화면 — 한 문장 요지"
[현재 1000×640] (x=0)   [개선 1000×640] (x=1080)   [작은 보드 360×420] (x=2160)   [메모 w=360] (x=2520~2600)
다음 줄 y = 이전 y + 보드 높이 + 120 + 300(제목 자리) 이상
```

- 보드 사이 80px, 줄 사이 120px 이상. 제목(title1)은 줄 위 223px 이상 띄운다.
- 보드 제목(`boards[].title`)에 "현재 · 문제 한 문장", "개선 · 바뀐 점 한 문장"을 적는다. 캔버스에서 보드 위에
  그대로 보인다.
- 메모(`notes`)는 `fill: "green"`, `w: 340~360`. 내용은 "지금은 … / 개선: · … · …" 형식 5~8줄.

## 현재 화면을 HTML로 옮기기

캡처를 붙이지 않고 다시 그린다. 이유: 개선 보드와 같은 척도·같은 데이터·같은 서체로 비교되고, 사용자가
캔버스에서 글자를 직접 고칠 수 있다.

- 앱의 토큰(색, 반경, 서체)을 그대로 쓴다. `index.css`의 값을 복사한다.
- 데이터는 테스트 데이터의 실제 문장을 쓴다(지어내지 않는다).
- 셸 구조만: 머리, 탭, 본문, 오른쪽 칸, 재생 바. 1000×620~640에 들어가게 본문은 3~6개 항목만.
- 버튼·입력은 진짜 `<button>`, `<input>`, `<label>`로, 아이콘은 인라인 stroke SVG로. 이모지는 쓰지 않는다.
- 각 보드는 `<!doctype html>` + `<script src="./support.js"></script>` + `<x-dc>` 뼈대, 끝에
  `data-props='{"$preview":{"width":W,"height":H}}'`. Google Fonts(Noto Sans KR)는 `<helmet>`에 링크.

## 개선 보드에 담을 것

- 바뀌는 부분만 바꾼다. 나머지는 현재 보드와 글자 하나까지 같아야 차이가 보인다.
- 숨긴 것(옵션 창, 메뉴, 접힌 패널)은 작은 보드로 옆에 따로 그린다.
- 색 규칙·스타일 타일 같은 "시스템" 제안은 1200×560 보드에 왼쪽 샘플 UI, 오른쪽 색 견본·모양 견본으로.
- 수치(대비, 크기)는 보드 안이 아니라 메모에 적는다.

## 보고에 적을 것

- 캔버스 링크, 줄별로 "현재 → 개선" 한 줄 요약, 각 줄의 예상 버전(토큰만이면 수 버전, 구조면 부 버전).
- "캔버스는 비공개라 다른 사람에게 보여 주려면 페이지의 공유 메뉴에서 열어야 한다."
- "보고 고르면 그대로 코드에 반영하겠다"고 끝낸다. 취향이 갈리는 것은 그림을 먼저 보고 고르게 한다.
